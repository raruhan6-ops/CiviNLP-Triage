CIVINLP-TRIAGE: CURRENT PROBLEMS TO FIX
=======================================
Based on a read-through of CiviNLP-Triage-main.zip (source, scripts, tests,
configs, CI, docs) and a comparison with the CiviNLP.docx paper outline.

How I checked: I read all files in the zip and ran the tests that do not
need the missing models package (pandas 3.0.2): 8 of 9 passed.
NOT verified: the missing models package, ruff/black, the network
pipeline, DistilBERT training.

Priority key:  [P1] blocks use or invalidates results
               [P2] real bug or misleading behaviour
               [P3] cleanup


-----------------------------------------------------------------
A. BLOCKING PROBLEMS
-----------------------------------------------------------------

[P1] 1. src/civinlp/models/ is missing from the repo
     Cause: .gitignore contains "models/", which matches ANY folder named
     models, including the source package.
     Effect: scripts, API, UI, eval and tests import
     civinlp.models.{baseline_rules, tfidf_lr, transformer, calibrate}
     and fail with ModuleNotFoundError on a fresh clone. CI fails too.
     Fix: change the ignore rule to "/models/" (root weights folder only)
     and add the real source files back from the original machine.
     If they are lost, rebuild them from how they are called.

[P1] 2. Pandas 3 breaks area grouping (tests/test_ranking.py::test_road_ranking)
     Cause: groupby over a one-item list now yields tuple keys, so
     area_id becomes ('A1',) instead of 'A1'.
     pyproject.toml does not pin pandas, so fresh installs get 3.x.
     Fix: group by the single column name when there is one column
     (or unpack the tuple), and pin a tested pandas range.

[P1] 3. "Road" data is not filtered to roads
     The default NYC 311 URL fetches the latest 2000 requests of EVERY
     complaint type, and preprocessing does not filter. Most rows end up
     labelled "other".
     Fix: add a $where filter (for example street/highway/pothole
     complaint types) and/or filter in preprocess_roads.py.

[P1] 4. Evaluation is circular
     - Labels are generated by the rule model from complaint_type +
       descriptor, and the model input is that same text, so F1 ~ 1.0
       is guaranteed. The rule baseline scores 1.000 against its own labels.
     - Ranking eval: "critical" areas are defined by rule-predicted high
       severity, the same signal the priority score uses.
     - NDCG uses the priority score as relevance, so ranking by that score
       gives NDCG = 1.0 exactly (I confirmed this by running the repo's
       own functions).
     Fix: add independent ground truth (hand labels and/or an outcome
     proxy such as repeat complaints or resolution time in a LATER time
     window) and compute metrics against it.

[P1] 5. Bridge pipeline is not wired up
     - No preprocessing maps NBI columns (DECK_COND_058, etc.) to ratings.
     - score_bridge's fallback only picks keys containing "rating", so raw
       NBI columns give severity 0.
     - NaN ratings can break min() (order-dependent result).
     - No bridge split function, no bridge tests on real NBI data,
       no bridge view in the UI, even though docs describe a road and
       bridge tool.
     Fix: write preprocess_bridges.py (column mapping, missing -> 9 as in
     the outline, numeric cleaning), handle NaN, add tests.


-----------------------------------------------------------------
B. CODE BUGS AND WEAKNESSES
-----------------------------------------------------------------

[P2] 6. Keyword matching uses substrings
     "rough" matches "through" (-> MEDIUM severity), "sign" matches
     "design"/"signal", "cave", "large" and others match inside longer
     words. Fix: word-boundary regex or token matching, plus tests.

[P2] 7. Duplicated or unused label logic
     KEYWORD_MAPPING is defined but unused. weak_labeling.py and
     RuleBaseline (missing, unverified) may implement the same rules twice.
     Fix: one source of truth.

[P2] 8. Priority score scaling
     Raw complaint count N_a (alpha=1) dominates: severity adds only
     2-6 points and the uncertainty penalty at most 1. Fifty minor
     complaints outrank five high-severity ones.
     Fix: normalise terms (for example per-area percentile or min-max),
     then tune weights with a sensitivity analysis.

[P2] 9. Zip codes become floats
     Reading CSV with missing values makes incident_zip float, so
     area_id likely comes out as "10001.0".
     Fix: read as string (dtype=str) and normalise to 5 digits.

[P2] 10. PII redaction is narrow
     Only emails and phone numbers; no names or addresses. The email
     regex has a stray "|" in [A-Z|a-z]. The phone regex can redact any
     10-digit number.

[P2] 11. Logging file handler never attached
     setup_logging skips adding handlers when the root logger already has
     some, and modules call logging.basicConfig at import time first.

[P2] 12. evaluate_all does not compute calibration
     No ECE and no temperature scaling in the evaluation script.
     DistilBERT result is still "Pending" in the README.
     train_models uses 2 epochs while configs/roads.yaml says 3 (verify).

[P2] 13. Downloader ignores --limit when the URL already has $limit.
     Also appends "&" even if the URL has no "?".

[P2] 14. split.py: val_size formula is wrong when test_areas is given
     explicitly (still uses test_frac); can go negative when few rows
     remain.

[P3] 15. No __init__.py in subpackages (api, data, eval, labels, ranking,
     ui, utils). Works as namespace packages but is fragile.

[P3] 16. Streamlit app
     - sys.path.append points at the repo root, not src/.
     - use_container_width is deprecated in recent Streamlit.
     - session_state keeps stale data when the data source changes.
     - Reloads the model on each rerun.

[P3] 17. Pydantic "class Config" is deprecated (use model_config).

[P3] 18. FastAPI has no authentication and no cap on batch size.

-----------------------------------------------------------------
D. GAPS BETWEEN THE PAPER OUTLINE AND THE CODE
-----------------------------------------------------------------
(The docx is an outline, so these are to-dos, not errors.)

- No count-only (H1), recency (H2) or condition-only (H3) baselines,
  and no "severity only" ablation in the code.
- NDCG in the outline uses gain 2^rel - 1 with rel = raw score
  (overflows); the code uses linear gain. Pick one and use an
  independent relevance label.
- No uncertainty-based manual-review routing is implemented or
  evaluated (RQ4).
- No bridge experiments exist (RQ2).
- The model input is only complaint_type + descriptor. The public NYC 311
  data has no narrative text, so the "free-text NLP" framing and the
  example complaints in the outline cannot come from this data.
- Outline mentions closed_date, early stopping, hyperparameter tuning;
  the code uses none of them.
- Area split: code reserves areas up to ~20% of ROWS; outline says 20% of
  zones.
- Outline has no references, no dataset size/date range, and uses
  "leakage-free" even though weak labels leak by construction.
